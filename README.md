# Практична робота: читабельність та відповідність стандартам коду

## 1. Модулі та залежності

- **1.1.** Змішування ESM (`import`) та CommonJS (`require`) замінено єдиним стилем ESM.
  - **Проблема:** в одному файлі використовувалися обидві модульні системи, через це код не буде працювати ні в браузері, ні стабільно в Node.js. Тепер використовується лише `import`.
- **1.2.** Імпорт `import * as X from 'fs'` замінено на точковий `import { readFileSync } from "node:fs"`.
  - **Проблема:** імпортувався весь модуль, хоча потрібна одна функція. Префікс `node:` однозначно вказує на вбудований модуль Node.js.
- **1.3.** Прибрано невикористовувані змінні `a`, `b`, `c`, `d`, а також дубль констант `PI` та `Pi`: використовується вбудований `Math.PI`, а скорочене значення `3.14` з оригіналу збережено як `PI_SHORT`.
  - **Проблема:** зайві змінні засмічують код і ускладнюють його розуміння.

## 2. Змінні та константи

- **2.1.** Усі `var` замінено на `const` або `let`, якщо значення змінюється.
  - **Проблема:** `var` має функціональну область видимості та піднімається, що призводить до плутанини й помилок. `const`/`let` мають блочну область видимості, а `const` ще й унеможливлює випадкове перевизначення.
- **2.2.** Усунено неявні глобальні змінні (`d = 4`, `FLAG`, `Flag`, `fLaG`).
  - **Проблема:** присвоєння без оголошення створює глобальну змінну, яка може випадково перезаписати інші дані. Змінні `FLAG`/`Flag`/`fLaG` відрізнялися лише регістром і не несли змісту, тому були видалені.
- **2.3.** Три однакові змінні `DATAFILE`, `DataFile`, `data_file` об'єднано в одну константу `DATA_FILE`.
  - **Проблема:** дублювання та різні стилі іменування одного й того ж значення.
- **2.4.** «Магічні» числа та рядки винесено в іменовані константи (`MIN_SQUARE_VALUE`, `DEFAULT_MODE`, `KNOWN_MODES`, `STEP_DELAYS_MS` тощо).
  - **Проблема:** числа без назви незрозумілі та їх важко змінювати.
- **2.5.** Прибрано зайві крапки з комою (`let t=undefined;;;;`).

## 3. Іменування та стиль оформлення

- **3.1.** Єдиний стиль іменування: `camelCase` для функцій і змінних, `UPPER_SNAKE_CASE` для констант.
  - **Проблема:** поєднання `doThing` / `dothing` / `DO_THING`, `calc` / `Calc`, `f` / `F` створювало плутанину і потенційні помилки.
- **3.2.** Функціям із неінформативними іменами надано змістовні назви:

  | Було           | Стало             |
  | -------------- | ----------------- |
  | `f`            | `formatUser`      |
  | `calc`         | `sum`             |
  | `doThing`      | `squareAndFilter` |
  | `sortBad`      | `sortDescending`  |
  | `sortBadAgain` | `sortAscending`   |
  | `messyRead`    | `readDataFile`    |
  | `hell`         | `runSteps`        |

- **3.3.** Єдиний стиль форматування: відступи в 2 пробіли, подвійні лапки, обов'язкові крапки з комою, один оператор на рядок, пробіли навколо операторів. Прибрано змішування табів і пробілів.
- **3.4.** Усі ключі об'єктів приведено до одного стилю (`name`, `age`, `city`).
  - **Проблема:** `Name` / `age` / `City` / `Age` / `city` використовувалися хаотично, тому функція `F` взагалі виводила `undefined`.
- **3.5.** Розбиття довгих фрагментів на окремі функції (без нової логіки): з `main` винесено `parseNumbers` (розбір рядка з даними), `getMode` (визначення режиму), `buildMessage` (формування службового рядка, що раніше було змінною `msg`) та `showOnPage` (виведення на сторінку).
  - **Проблема:** `main` містила десятки операцій в одному рядку й виконувала кілька різних завдань одночасно, що ускладнювало читання та повторне використання коду.

## 4. Усунення дублювання коду (DRY)

- **4.1.** Три копії функції `doThing` / `dothing` / `DO_THING` замінено однією `squareAndFilter`.
- **4.2.** Чотири способи підрахунку суми (`calc`, `Calc`, `Array.prototype.sum`, `Array.prototype.Sum`) замінено однією функцією `sum` на основі `reduce`.
- **4.3.** Дві функції сортування, які виконували однакову роботу різними алгоритмами, замінено двома короткими функціями на основі вбудованого `Array.prototype.sort` з коректним компаратором.
- **4.4.** Два цикли, що формували однакові рядки для користувачів, замінено одним викликом `USERS.map(formatUser)`.
- **4.5.** Прибрано повторні виклики однієї й тієї ж функції з тими самими аргументами та повторювані умови (`mode == 'x'` двічі, `FLAG == true` двічі).
- **4.6.** Функцію `main` більше не викликають двічі.

## 5. Порівняння та умови

- **5.1.** Усі `==` замінено на `===` (де порівняння взагалі потрібне).
  - **Проблема:** `==` виконує неявне приведення типів (`0 == false`, `null == undefined`), що призводить до неочевидних результатів.
- **5.2.** Ланцюжок умов `mode == 'x' || mode == 'y' || ...` замінено на `KNOWN_MODES.includes(mode)`.
- **5.3.** Прибрано мертвий код: гілки `if (false)`, `while`-цикли без дій, подвійні порожні цикли, умову `true == true == true`.

## 6. Безпека та побічні ефекти

- **6.1.** Функцію `weirdMath` збережено, але переписано без `eval` та `with`.
  - **Проблема:** `eval` виконує довільний рядок як код (вразливість до ін'єкцій), `with` заборонений у strict mode (ES-модулі) і робить область видимості непередбачуваною.
  - **Рішення:** функція тепер приймає не рядок-вираз, а число. На початку виконується перевірка: якщо значення не є скінченним числом (`typeof value !== "number"` або `!Number.isFinite(value)`), викидається `TypeError`. Таким чином, передати в функцію код або рядок неможливо, а будь-який коректний вхід гарантовано дає числовий результат. Математичні функції викликаються явно через `Math.floor`, `Math.random`, `Math.sin`, `Math.cos` (замість `with(Math)`). Формула збігається з оригінальною: `значення + floor(random*10) - sin(PI/2) + cos(Pi)`.

  > [!IMPORTANT]
  > Зміна сигнатури (рядок → число) є свідомою: безпечно обчислювати довільні рядки-вирази без власного парсера неможливо, а додавати нову логіку, якої не було в оригіналі, не потрібно.

- **6.2.** Розширення вбудованого прототипу `Array.prototype` (методи `sum` і `Sum`) замінено звичайною функцією `sum(numbers)`, яку не прив'язано до глобального об'єкта.
  - **Проблема:** розширення вбудованих об'єктів може зламати сторонні бібліотеки та спричинити конфлікти імен у майбутніх версіях мови. Функціонал підрахунку суми повністю збережено.
- **6.3.** Функції більше не змінюють вхідні дані: у `squareAndFilter` замість `z.push()` створюється новий масив, у сортуванні використовується копія.
  - **Проблема:** мутація аргументів призводить до неочікуваних побічних ефектів.
- **6.4.** Виклик `document.write` замінено функцією `showOnPage`, яка створює елемент `<p>` через `document.createElement` та додає його за допомогою `textContent` і `append`.
  - **Проблема:** `document.write` перезаписує сторінку після її завантаження, блокує парсинг і небезпечний при вставці HTML-рядків (ризик XSS). `textContent` вставляє текст як є, без інтерпретації HTML. У Node.js, де `document` відсутній, функція нічого не робить, тож код не падає. Експорт `window.main` у браузері не потрібен, бо `main` експортується як ES-модуль; перевірки `typeof` залишено лише там, де це потрібно (`location`, `process`, `document`).

## 7. Обробка помилок

- **7.1.** Порожні блоки `catch`, які мовчки ігнорували помилки, замінено обробкою з виведенням попередження та використанням даних за замовчуванням.
- **7.2.** Замість `throw "рядок"` (`throw "no fs"`) більше не використовуються рядки як виключення.
- **7.3.** Прибрано заглушки з вигаданими даними `"stub,1,2,3"` та дублюючі варіанти значень за замовчуванням.
- **7.4.** Головну функцію обгорнуто в `.catch()` з встановленням коду завершення процесу (`process.exitCode = 1`) при помилці.

## 8. Асинхронність

- **8.1.** «Піраміду смерті» (чотири вкладені `setTimeout`) замінено на `async/await` з допоміжною функцією `delay` та циклом `for...of`.
  - **Проблема:** глибока вкладеність колбеків погано читається та складна в підтримці й обробці помилок.
- **8.2.** Ланцюжок `Promise` із порожніми `.then()` і `.catch()`, що ковтав помилки, замінено на `async/await` з явним `try/catch`.
- **8.3.** `main` зроблено `async`-функцією, що повертає `Promise`.

## 9. Структура файлу та запуск

- **9.1.** Великий довгий рядок конкатенації замінено шаблонним літералом (template literal), складну довгу логіку розбито на невеликі функції з однією відповідальністю (`buildMessage`, `getMode`, `parseNumbers` тощо).
- **9.2.** Довгий рядок виведення `Final` замінено на виведення одного об'єкта.
- **9.3.** Автоматичний запуск `main()` при імпорті прибрано: тепер він виконується лише коли файл запущено напряму. Це дозволяє імпортувати функції в інші модулі (і тестувати) без побічних ефектів.
- **9.4.** Експортуються лише потрібні функції без дублікатів (`main`, `sum`, `squareAndFilter`, `readDataFile`, `parseNumbers`, `sortAscending`, `sortDescending`, `formatUser`, `weirdMath`, `showOnPage`).
